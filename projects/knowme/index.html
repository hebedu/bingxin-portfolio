3.1 Prompt 规则系统：分层维护，而不是堆成一条提示词

对应问题1 · 快速理解我 ／ 问题2 · 回答可信 ／ 问题3 · 持续留下
输入与规则装配：先用结构化表单填写并校验出生日期、时间和地点，避免格式问题造成计算错误或流程卡死；再根据 Intent 装配对应规则，并以统一 Tone 保持稳定的人格与关系感。
分层 System Prompt

规则各自独立维护

人格 / 风格 / 拒绝规则 / 领域规则 / 输出模板分别装配，改风格不触碰领域知识。

bazi：四柱、十神、五行旺衰、格局、大运、流年

astrology：行星、星座、宫位、相位（Tropical + Placidus）

synastry：两人比较盘 + 组合盘

Intent Prompt

按提问状态选择处理规则

没有明确问题：从自我探索报告开始引导。

有明确问题：直接承接个性化追问，并识别是否属于高风险问题。

问题模糊：先澄清关键条件，再提供带不确定性标记的试探性回答。

合并重叠 Intent补充真实用户语言识别安全风险设置独立 Fallback
Tone Rules

温柔、克制的陪伴者

用户常在迷茫、焦虑或面临选择时来到 KnowMe。人格需要承接情绪，但不能借命理制造权威感与依赖。

温柔：先理解处境，不评判、不说教，让用户愿意继续表达。

克制：不夸大确定性、不渲染恐惧，不用“只有我懂你”强化依赖。

陪伴者：提供视角、问题和行动建议，把重大决定留给用户。

稳定人格 + 随场景变化的行为规则
不变项 · Hard Constraints事实来自引擎不解释内部方法论禁止伪精确预测推测必须标记失败必须降级长度由代码保证Fallback：模型或输出失败时进入降级路径；使用 MIN_CHARS + 续写循环保证长度。
维护收益：风格、Intent、拒绝规则与领域知识独立修改，影响范围可预测。

3.2 Memory：按生命周期管理，而不是全部记住

对应问题3 · 持续留下（后续设计）／ 问题2 · 回答可信
为了让长期对话既能延续、又不越过信任边界，记忆的取舍标准不是“信息有没有出现”，而是未来是否仍然有助于正确理解用户。
01 · 记忆内容与生命周期
Memory用途生命周期
Birth facts身份锚点长期
系统识别的长期背景个性化长期

AI 自动推断出的性格不直接写入长期记忆默认不存
02 · 记忆写入与控制

长期记忆必须可解释、可控制

写入：系统从对话中自动识别未来仍有帮助的长期背景，并写入长期 Memory，无需用户逐条确认。

控制：用户可以查看、修改和删除长期 Memory。

敏感信息：采用更高写入阈值，不因一次对话自动沉淀。

3.3 Structured Rules：为什么当前优先结构化规则

对应问题2 · 回答可信 ／ 问题3 · 持续留下
当追问超出原报告的覆盖范围，真正的风险不是模型“答不出来”，而是它会回到预训练知识临场发挥，导致解释口径在不同轮次和报告间漂移。因此选择 Structured Rules，是为了获得跨轮、跨报告的一致性，而不是让单次回答显得更聪明。
01 · 问题出现追问超出原报告报告讲事业，用户继续问亲子关系；原报告没有可复用的解释材料。
→
02 · 原有结果模型临场发挥依赖预训练知识也能回答，但跨轮次会出现口径与人格漂移。
→
03 · 产品决策全量注入结构化规则模型根据 facts 中真实出现的字段，反查同一套知识规则。
→
04 · 得到结果解释稳定且有条件报告与追问共享口径，并能先判断条件是否成立，再解释含义。
为什么不是 Vector RAG

这里需要精确反查，不是语义相似

命盘符号和条件已经结构化。向量召回会增加错召回与漏召回的不确定性，而不能替代 facts 的精确匹配。

为什么现在可行

规则规模可控，并且可缓存

三套规则约 80.3K 字，位于静态 Prompt 前缀。持续注入能换取一致性，边际推理成本接近于零。

如何建立 Structured Rules 并生成链路

规则表的生成，是把古籍与领域资料提炼为包含知识含义、适用条件和使用边界的结构化规则，再接入生成链路。
01 · 知识来源古籍与领域资料八字、星盘、合盘资料，以及 KnowMe 明确选择的产品解释口径。
→
02 · 规则化定义含义、条件和限制把知识整理为 meaning、key_conditions 与 usage_note。
→
03 · 运行时静态全量注入规则进入可缓存的 Prompt 前缀；模型只反查 facts 中真实存在的字段。
→
04 · 输出条件化解释先判断规则是否成立，再按统一口径生成，并遵守使用边界。
一条规则的结构

Meaning + Conditions + Usage

meaning：符号在 KnowMe 中如何解释。
key_conditions：什么盘面条件下解释成立。

一个实际判断

不是看到正财，就输出通用性格

模型先检查正财是否真实存在，以及旺衰、藏露、有无制化；条件成立后，才解释它在这个人身上的具体含义。

facts → 正财存在 → 条件成立 → 个性化解释
规则的使用边界

规则不只提供解释，也约束不能怎么讲

没有 facts 支撑的符号不引用；不同盘型不混读；知识覆盖不足时不硬编；争议观点不强行合并；次要信息不扩写成主线。

这个项目让我形成的 AI 产品原则

01

能算的都不留给模型

确定性事实交给程序；LLM 更适合解释、推理、表达、对话。

02

静态在前，动态在后

Prompt 顺序也是成本参数，提高前缀缓存利用率。

03

分层隔离优于巨型 Prompt

人格、规则、Intent、安全、结构分别修改和测试。

04

装配优于分支

根据当前 Intent 只装配需要的规则；无关内容不进入 Prompt，避免让模型在互相冲突的要求中自行选择。

05

约束要有单一信源

很多冲突不是模型不听话，而是系统自己给了不同要求。

06

能用代码验证的，不只依赖模型自觉

结构靠 Prompt；长度靠代码；事实靠 Validator；失败靠 Fallback；安全靠 Trust Boundary；评估器也需要独立 Eval。

最终，我希望 KnowMe 证明的不是“我会做一个 AI 命理产品”
